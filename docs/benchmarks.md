## Notes

- Speedup is Naive 1T over BVH SAH on all threads.
- A ray is every ray traced: camera rays plus every bounce.
- `~` marks an estimate. Brute force on a mesh takes hours at full size, so naive mesh runs render a smaller 1 spp image of the same view and the time is scaled up by the camera sample count. Mrays/s is measured directly.
- Scenes with only a handful of objects run faster without the BVH: the box tests cost more than they save. It pays off from meshes upwards.
- Output is byte-identical across thread counts (checked by `test_renderer`). `test_bvh` checks both BVH builds return the same closest hit as brute force on 20k random rays.

Reproduce: `kiln_bench --out docs/benchmarks.md` from the repo root.
